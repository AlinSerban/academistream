# Definition of Done

A change is done when:

1. Acceptance criteria / intended behavior are met
2. Relevant tests exist for critical paths (or N/A is noted for docs-only work)
3. No secrets committed
4. Schema changes include migrations (when we have a DB schema)
5. README / run docs updated if how-to-run changed
6. Ready for review (PR or equivalent)

## Branch naming (light)

Prefer descriptive names, e.g. `feature/compose-stack`, `feature/tenant-memberships`.
